# ADR-0001：第一阶段公开契约只有 CLI，不承诺 Node library API

状态：accepted（2026-07-06；决策形成于首轮 MVP，本文档随定位确认补记）

## 背景

`agent-plugkit` 的稳定入口是 CLI。内部 TypeScript 模块为命令实现服务，但包内存在可复用模块
并不自动形成对外兼容承诺。

## 决策

1. 第一阶段的稳定公开契约只有三样：`agent-plugkit` CLI、配置 schema（`marketplace.yaml`、`plugin.yaml`）、生成物契约。
2. 内部 TypeScript 函数不作为公共 API 文档化，semver 不为其内部签名负责。
3. 核心命令逻辑与终端呈现（chalk/console）保持分层，但内部结构化接口仍不等于公开 library API。
4. 不为假设中的调用方预先发布浅包装；只保持内部边界可演进，等真实外部需求出现再评估公开。

## 后果

- 好处：semver 维护负担被限制在 CLI 行为与文件契约上；内部重构自由度高。
- 代价：程序化集成方短期只能通过子进程调用 CLI；命令层编排与呈现仍需保持可维护的内部边界。
- 触发重新评估的条件：出现真实的外部程序化调用需求，且子进程方案被证明不够用。
