# 终端交互规范

- 状态：active
- 适用表面：`agent-plugkit` CLI
- 当前交互命令：`install-repo`
- 行为契约：[`packages/cli/README.md`](../../packages/cli/README.md#agent-plugins-and-client-marketplaces)
- 最后更新：2026-08-16

本文是仓库终端呈现的 canonical。它拥有信息层级、键盘映射、状态呈现和可访问性；命令参数、
来源、目标语义、退出码、幂等性与副作用由 CLI README 和端到端测试共同约束，本文不复制实现细节。

## 信息层级

- 命令必须在无颜色、日志重定向和屏幕阅读器环境中保留完整语义。
- 显式选择模式按“来源 → 将执行的目标动作 → 分组结果 → 退出码”从上到下呈现，不显示选择器。
- 交互模式先显示编号目标及探测状态，再沿用相同的执行与结果区域。
- 每个自动动作开始前单独一行显示客户端名称，以及可审计的 executable 和逐项引用 argv；VS Code
  显示用户配置目标，不伪装成 shell 命令。
- 最终结果固定分为“已完成”和“未完成”；空分组显示“无”，避免读者从缺行推断状态。
- 恢复入口紧跟未完成项缩进一行显示，不汇总成与目标失去对应关系的尾注。

## 编号选择器

交互入口完成只读探测后显示稳定编号列表：

```text
请选择要注册 Marketplace 的 agent：
  1. Claude Code       [可自动]
  2. Codex             [可自动]
  3. Grok Build        [可自动]
  4. GitHub Copilot    [缺少 CLI]
  5. VS Code           [可自动]
  6. Cursor            [需手动]

默认：1,2,3,5
输入编号（逗号分隔），输入 all 选择全部，直接回车接受默认：
```

- `[可自动]`：当前探测结果允许命令或配置写入。
- `[缺少 CLI]`：原生 executable 不存在。
- `[不可用]`：executable 存在但能力不足，或官方 VS Code 无法确认。
- `[需手动]`：平台没有本轮可依赖的公开自动注册接口。
- 默认集合以显示出的编号表达；没有默认目标时显示“默认：无”。
- `1,2,4` 与单个编号选择相应行，`all` 选择全部显示项，直接回车接受显示的默认集合。
- 忽略逗号两侧空白并去重；范围、未知编号和其他文字走普通错误呈现，不在同一屏循环猜测输入。
- `Ctrl-C` 在提示刚打印、readline 正在建立或已经读取时都使用同一中断状态立即关闭，打印一行
  `[中断]`；不清屏，也不打印成功分组。

## 运行与结果呈现

每个目标完成后立即打印一行文字状态，最终再按“已完成/未完成”分组汇总。状态标签固定为：

```text
[完成] Claude Code：Marketplace 已注册
[缺少 CLI] GitHub Copilot：未找到 copilot；安装或升级后重试
[需手动] Cursor：Dashboard → Plugins → Add Marketplace → Import from Repo
[失败] VS Code：settings.json 不是合法 JSONC，没有覆盖原文件
```

VS Code 成功行同时提示重新加载窗口；组织策略覆盖用户设置属于客户端后续状态，不改写本次
“配置已注入”的结果。Cursor 文案必须包含 Team/Enterprise 和管理员前提，不能写成已完成。
运行期中断仍打印完整分组汇总；后续目标若已知为缺 CLI 或需手动，保留其原状态和恢复入口，
只有原本可自动执行但未启动的目标标为 `[中断]`。

## 窄终端与可访问性

- 不使用光标定位、清屏、覆盖行、spinner 或动画；每个状态是可顺序朗读的普通文本行。
- 不用颜色承载状态，因此 `NO_COLOR`、不支持 ANSI 的终端和日志重定向无需替代样式。
- 窄窗口使用终端自然换行；不截断来源、配置路径、失败原因或恢复步骤，不绘制依赖固定宽度的边框。
- 编号、客户端名和方括号状态同时存在；屏幕阅读器无需根据对齐空格判断目标或结果。
- 长路径和 argv 保持单个逻辑动作一行开始；自然换行后的续行不插入新的状态标签。
